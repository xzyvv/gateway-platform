# API 错误码表

本文是网关 HTTP API 业务码的唯一对外文档。代码侧唯一来源是
`gateway-api/src/web/error_codes.rs`（常量 + `ALL_CODES`），前端文案表是
`gateway-web/src/utils/errorCodes.ts`。三者由测试强制同步，不要在任何一侧手工「补一个码」。

## 1. 响应信封

```json
{ "code": 4002, "message": "不支持的协议: foo", "data": null,
  "retryable": false, "category": "client" }
```

- `code == 0` 是唯一成功码；非 0 一律失败，`message` 是给人看的现场文案。
- HTTP 状态由 `code` 的号段推导（见 §2），唯一例外见 §4。
- `data` 在失败时恒为 `null`，不要依赖其中字段。
- 失败响应额外带两个机器可读字段（成功响应不出现）：
  - `retryable: bool` —— 同请求原样重发是否可能成功；`WRITE_UNCERTAIN(5102)` 恒为
    `false`，`4xxx` 段（除 4090/4503/4290）恒为 `false`；
  - `category: string` —— `client`（改参数）/ `device`（查现场）/ `auth`（换凭证）/ `server`（联系维护方）。

客户端不必再自己维护「哪些码能重试」的硬编码表。

## 2. 号段与 HTTP 映射

| 段 | 语义 | HTTP |
|---|---|---|
| `0` | 成功 | 200 |
| `1xxx` | 配置 / 序列化 | 400 |
| `2xxx` | 本地 IO | 500 |
| `3xxx` | 协议 / 对端无应答 | 500；3001 → 504 |
| `4xxx` | 客户端可纠正 | 400；4004 → 404；4010 → 409；4290 → 429 |
| `5xxx` | 服务端执行失败 | 500；5003 → 503 |
| `6xxx` | 业务校验（设备分组） | 400 |
| `7xxx` | 授权 | 403 |
| `8xxx` | 鉴权 | 8000-8002 → 401；8003-8099 → 403；8101 → 503 |
| `9999` | 内部错误 | 500 |

`9xxx` 段已废弃（原 9000「资源不存在」与 4004 重复）。

## 4. 特例：协议工具端点的「HTTP 200 + 非零 code」

`/api/protocol-tools/*` 的帧级失败刻意分离两层语义：

- **HTTP 状态**回答「接口通不通」——调用链路正常即 200；
- **业务码**回答「设备通不通」——失败给出 3000 / 3001 / 4090 / 4503。

这类响应体额外带 `"frame_error": true`（与 HTTP 200 严格等价）。**只按 HTTP 判定的
调用方会把这些失败当成功**；请用 `code != 0` 或 `frame_error` 判定。请求参数类错误
（4000 / 4001 / 4002 / 4004）不受此特例影响，仍按 §2 返回 400 / 404，`frame_error=false`。

详见 [协议工具 API](api-protocol-tools.md)。

## 5. 统计指标标签 ↔ 业务码

`/api/diagnostics` 的 `last_error_code` 是**统计层标签**（给 Prometheus 分组用），
与本文的业务码不是同一套。映射由 `gateway-api/src/web/collect_error_map.rs` 固化：

| 统计标签 `last_error_code` | 业务码 | 含义 |
|---|---|---|
| `TIMEOUT` / `NO_REPLY` | 3001 | 设备或总线在超时内没有应答 |
| `IO` | 2000 | 本地 IO 失败 |
| `CRC` / `DECODE` / `EXC_xx` | 3000 | 帧校验失败 / 解码失败 / 从站异常（`EXC_02` 等） |
| `BUS_CLOSED` | 4503 | 总线已关闭 |
| `BUSY` | 4090 | 总线忙 |
| `CONFIG` | 1000 | 配置错误 |
| `OTHER` | 9999 | 未分类 |

多个标签合并到同一业务码是刻意的：客户端处置动作相同（如 CRC 与解码失败都要查现场干扰）。

## 6. 客户端处置建议

| 场景 | 处置 |
|---|---|
| 4001 / 4002 / 4004 / 4009 / 4010 / 4011 / 6001 / 6002 | 提示用户改输入或换名字；不要自动重试 |
| 4290 | 按 `Retry-After` 退避重试 |
| 5101 | 可安全重试 |
| 5102 | **禁止自动重试**：先调用读接口核实设备实际值，再决定是否重发 |
| 3001 / 4090 / 4503 | 检查总线与设备状态（暂停采集、检查接线、确认从站地址） |
| 8003 / 8004 / 8005 | 提示权限不足，需换主 token 或调整 API 密钥 scope |
| 7001 / 7003 | 引导导入 / 更新授权 |
| 2000 / 5000 / 5002 / 5003 / 9999 | 服务端故障：记录 `message` 与时间，联系维护方 |

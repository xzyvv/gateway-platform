# 功能摸底台账（2026-11）

> **性质**：按功能域的前后端功能盘点基线。用于回答「这个功能域现在到底有什么、代码在哪、有没有已知债务」。
> **本轮只读**：本次摸底期间未修改 `gateway-platform` 任何源码文件。
> **范围**：`gateway-core` / `gateway-api` / `gatewayd`（后端）+ `gateway-web`（前端调试 Web）。
> **硬约束**：本项目只补全现有功能，不新增功能面。台账中所有「建议动作」均不得引入新功能。

---

## 0. 摸底方法与口径

| 阶段 | 内容 | 结果 |
|---|---|---|
| S0 基线对齐 | 复用既有 ROI-01~27 审计、三份不变式清单、`docs/config-reload-matrix.md` | 避免重复报已有债务 |
| S1 自动化扫描 | clippy / vue-tsc / eslint / cargo test / vitest / api-test-coverage | 6 项门禁实测完成，2 项失败、1 项部分失败 |
| S2 功能域配对深查 | 10 个功能域，逐域 7 步审计动作（前端入口 → 前端实现 → 后端端点 → 后端实现 → 语义口径对照 → 债务识别 → 证据固化） | 覆盖全部 10 域 |
| S3 汇总落盘 | 本目录三份文件 | 见 `02` / `03` |

**债务分类**：结构债（组织/超大文件/重复实现）、语义债（同名不同义 / 口径相反）、架构债（层次越界 / 全局状态 / 锁序）、文档债（文档与实现不符）、测试债（断言陈旧 / 覆盖缺口）、契约债（前后端模型不一致）。

**定级**：P0 阻断（功能错或安全）/ P1 必修（有正确性或稳定性风险）/ P2 建议（可维护性）/ P3 记录。

**存量与新增分离**：本台账区分「已登记未关闭存量」与「本次新发现」，同一问题不重复登记。

- 16 组均有至少一个前端消费方，无「后端有端点前端无入口」的整组孤儿。

- 唯一端点级缺口：`POST /api/protocol-tools/iec104/ioa-read` 无测试覆盖（`scripts/check_api_test_coverage.py` 实跑）。

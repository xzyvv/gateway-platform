## 3. 待处理债务清单（按类别）

### 3.1 结构债

**DD-47 · 字节工具三套并存，无单一真源**（P2，D7）— ✅ **已修 2026-11-23**
- **现象**：`hexToBytes` 在 `utils/hexDump.ts:16` 与 `utils/frameParser.ts:23` 各实现一份；`utils/hexFrame.ts` 另提供 `normalizeHex`/`isValidHex`。三个模块的字节解析口径无共享实现。
- **影响**：帧解析、HEX 展示、输入校验各自为政；协议调试台的解析结果是现场排障唯一依据，口径分裂会导致同帧在不同页得到不同结论。
- **证据**：`src/utils/hexDump.ts:16`、`src/utils/frameParser.ts:23`、`src/utils/hexFrame.ts:11,22`。
- **建议**：收敛为 `utils/hexCodec.ts` 单一实现，`hexDump`/`frameParser`/`hexFrame` 均改为引用；barrel 保持对外符号不变。
- **实际修复**：已建 `utils/hexCodec.ts` 单一真源（含五项工具函数）；三处旧模块改为 re-export / import，对外符号与 import 路径全不变。统一口径为「非法输入返回空数组」（消除旧 frameParser 的 NaN 隐患），保留去 `0x` 宽容特性。新增 `hexCodec.spec.ts`（10 条，含旧入口等价钉子）。
- **新增功能面**：否。

### 3.2 语义债 / 契约债

**DD-27 · 前端内置回放会话含后端不存在的 `s3`**（P2，D7）— ✅ **已修 2026-11-23**
- **现象**：`usePacketReplay.ts:30` `BUILTIN_IDS = new Set(['s1','s2','s3'])`；后端 `gateway-api/.../packet_replay/sessions.rs` 只内置 `s1`/`s2`（`:3,13,93`）。
- **影响**：前端把 `s3` 当预置会话（灰色不可删），但该 ID 在后端不存在，点开必然 404。属前后端口径漂移。
- **建议**：以后端为准，前端移除 `s3`；或后端补 `s3`。推荐前者（最小改动）。
- **新增功能面**：否。

**DD-30 · 报文编辑页写帧无二次确认**（P2，D7/D8）— ✅ **已修 2026-11-23**
- **现象**：`PacketEditor.vue:116-135` 的 `send()` 校验 HEX 合法性后直接 `sendFrame()` 下发，无写帧识别与确认；同域 `StepDebug.vue:71,198,216-217` 已有 `isWriteFrame()` + `confirmAction()`。
- **影响**：在生产总线上误填一帧写命令即真实下发，缺少同域已有的安全兜底。
- **建议**：把 `StepDebug` 的写帧识别与确认逻辑抽为共享 composable，`PacketEditor` 复用（收敛而非新增）。
- **新增功能面**：否。

**DD-48 · 从站扫描失败仍弹「扫描完成」成功 toast**（P2，D7）— ✅ **已修 2026-11-23**
- **现象**：`SlaveScan.vue:159,169` 无条件 `ElMessage.success("扫描完成…")`，而 `:164,174` 又把失败原因写入常驻 `scanError`。同屏成功 toast + 失败提示并存。
- **影响**：现场扫不到设备时先看到绿色「扫描完成」，与「把失败报成成功」同类，误导判断。
- **建议**：成功 toast 仅在真成功分支触发；失败态不报完成（对齐 DD-02/DD-03 已建立的"终态显式"口径）。
- **修复勘误（2026-11-23 实测）**：后端 `slave_scan.rs` 的 `summary` 与 `failed` 是互斥终态，当前前端 `onFailed` 已只设 `scanError`、不弹 success——**原清单描述的「失败弹成功」在当前代码里已不存在**。真实缺口是流式走 SSE、不经过 axios 拦截器，失败时没有任何 toast、只有内联错误。故本次修复为：`onFailed` 补 `ElMessage.error` + 原因常驻，并补 failed/aborted 两条回归测试钉住"不弹 success"。
- **新增功能面**：否。

> **范围**：仅 `gateway-web/`。与前四轮"技术债务"不同，本轮聚焦**运行时与加载性能**。
> **性质**：只读摸底，未改动任何源码。所有结论带 `file:line` 证据或实测数据；扫描命中逐条读码核实。

## 0. 结论先行

1. **项目已高度优化，没有"立即可动手且高收益"的性能点**。本轮深挖 8 个性能维度后，主流热点（首屏体积、高频实时推送、大列表、轮询调度、图表刷新、历史数据、内存增长）全部已有成熟优化并有实测数据或单测守护。
2. **唯一有明确数据支撑的残余空间**是首屏 echarts 主 chunk（188.6 KB gz）——但它是折线图核心，已模块化到只注册 LineChart + 基础组件，进一步裁剪收益不确定、风险高（见 §3）。
3. **列出 3 项"可做但低收益/高成本"的残余项**（§2）与 **7 项"不建议做"清单**（§4）。后者是本轮主要产出——防止把已优化的东西当成优化点反复折腾。
4. **建议**：当前不做代码改动；把精力放在业务功能上。若未来要优化，优先按 §2 的 ROI 排序，且每项先立实测基线再动手。

## 2. 残余优化项（可做，但收益低 / 成本高）

> 按 ROI 排序。均**不紧急**，当前无实际卡顿投诉。每项动手前先立实测基线。

### 2.1 首屏 echarts 主 chunk 188.6 KB gz —— 收益中，成本高/风险高

- **现状**：`vite.config.ts:130-139` 已将 graph/custom/bar/dataZoom/markLine/title/marker 拆到 `echarts-extra` 懒加载；主 chunk 只留 LineChart + Grid/Tooltip/Legend + CanvasRenderer（`echartsSetup.ts:19-34`）。
- **残余空间**：实时趋势页是核心高频页，用户进入它必然下载 188.6 KB。可研究方向：用 `echarts/core` 更细粒度注册、或评估 SVGRenderer 替代 CanvasRenderer 在少量点位场景的体积/清晰度权衡。
- **代价/风险**：echarts 内部模块耦合紧，裁剪需逐个验证图表不空白（项目有过"趋势图永久空白"的历史 bug，见 `useRealtimeChart.ts:34-37`）。**不建议轻易动**。

### 2.2 模板内联 `.filter().length` × 2 —— 收益极低，成本极低

- `ApiRateLimit.vue:11` `rules.filter(r=>r.enabled).length`、`UplinkNorthStatus.vue:157` `servers.filter(s=>s.running).length`。
- 两处数据是配置级小规模（限流规则 / 北向服务器，通常个位数），每次重渲染重算的开销可忽略。若顺手可提为 computed，但**不值得单独立项**。

### 2.3 RequestMonitor 200 行表格未虚拟滚动 —— 收益低，成本中

- `RequestMonitor.vue` 用 `DataTablePlain` 渲染最多 200 条日志，无虚拟滚动（表格主路径 `DataTable.vue` 有阈值自动切换，但此组件走的是 Plain 变体）。
- 200 行 DOM 在桌面端可接受；且日志条数有硬上限（`requestLog.ts:58`），不会出现万行卡顿。除非现场反馈该页卡顿，否则**不动**。

## 3. 一个被排除的"伪优化点"（避免误伤）

**Vue runtime compiler 裁剪**：首屏依赖里有个名为 `typescript-2dpABrj7.js` 的 chunk（15.5 KB gz），初看像"TypeScript 编译器被打进前端"。核实后确认是**误报**：

- chunk 内容是 Vue runtime 模块（`trustedTypes.createPolicy('vue')` 等），非 TS 编译器；`typescript` 仅在 devDependencies，源码零 import。
- chunk 内无 `compileToFunction` / `baseCompile` 等编译器特征，全项目也无运行时模板编译（` template:` 命中均为配置对象属性名，非 Vue 组件 template 选项）。
- 结论：加 `vue` runtime-only 别名收益不确定、有漏掉动态编译的风险，**明确不做**。

## 4. 不做清单（已优化或有意为之，明确不建议改）

| 疑似优化点 | 为什么不做 |
|---|---|
| 首屏再分包 / 减小首屏闭合集 | 159.4 KB 已在 190 KB 预算内，切换 CSS 按路由拆分已省 57 KB（详见 `check-bundle-size.mjs` 注释）；收益已被吃掉 |
| echarts 整体按需 / 换 SVGRenderer | 已模块化只注册折线图核心（§2.1），进一步裁剪收益不确定且有图表空白风险 |
| 实时页改 appendData 增量刷新 | 项目图表用内联 data 数组，`appendData` 必抛 TypeError——已作为死代码移除并记录（`echartsAppend.ts:8-12`），不要恢复 |
| 给 pointList / historyMap 加深层响应式 | 正是要避免的开销：1200 点位高频推送下深层代理成本与渲染同量级（`useRealtime.ts:69-71`） |
| 拆分 HubShell.vue 等大组件 | 体积属性能优化的反面——组件拆分不减少运行时开销；且全部 <800 行预算 |
|  polling 改回每页独立 setInterval | 共享调度器 + 并发闸门是为工控低配环境设计的（§1），回退会重新引入后台空转 |
| 给所有 v-for 补虚拟滚动 | DataTable 已有阈值自动切换；配置级列表（规则、服务器、选项）补虚拟滚动只增加复杂度 |

## 2. 本轮确认的改进点（均 P3）

### 2.1 原生 `prompt()` 与 Element Plus 交互不一致 —— 语义/一致性债（P3）

**证据**：
- `src/composables/acquisition/usePacketReplay.ts:157` `const name = prompt('新会话名称：', ...)`
- `src/views/acquisition/packet/PacketCapture.vue:153` `const name = prompt('回放会话名称：', defaultSessionName())`
- 对照：`src/composables/layout/useGatewaySwitcher.ts:154` 用 `ElMessageBox.prompt(...)`；`SlaveSimulator.vue:117` 同。

**问题**：项目是 Element Plus 体系，输入弹窗有 3 处，其中 2 处用浏览器原生 `prompt()`，1 处用 `ElMessageBox.prompt`。原生 `prompt` 的问题：① 视觉与全站 Dialog 不一致；② Tauri 桌面壳里样式突兀；③ 浏览器原生弹窗阻塞主线程；④ 无法被 `ElMessageBox` 的统一 mock 覆盖（对照 `SlaveSimulator.spec.ts:107/119` 已有 prompt mock 范式）。

**建议**：两处改用 `ElMessageBox.prompt`（沿用 `useGatewaySwitcher` 写法），并补对应 spec 覆盖确认 / 取消分支。风险低，纯 UI 层。

### 2.2 本地 `formatTime` 六处重复 —— 结构债（P3）

**证据**：以下 6 处实现同一套"秒/毫秒归一化 + 委托 `formatDateTime`/`formatTimeOfDay` + 空值兜底"逻辑：

| 文件 | 行 | 归一化写法 |
|---|---|---|
| `composables/uplink/useUplinkTester.ts` | 197 | 直接 `formatTimeOfDay(t)` |
| `composables/config/useConfigVersions.ts` | 52 | `t * 1000` |
| `views/uplink/UplinkPassthrough.vue` | 96 | `t > 1e12 ? t : t * 1000` |
| `views/system/maintenance/CellularStatus.vue` | 205 | `t > 1e12 ? t : t * 1000` |
| `composables/data/useHistoryQuery.ts` | 165 | 已是毫秒，`new Date(ts)` |
| `utils/realtimeFormat.ts` | 92 | `t < 1e12 ? t * 1000 : t` |

项目已有单一本源 `utils/datetime.ts`（`formatDateTime` / `formatTimeOfDay`），但"秒/毫秒判断 + 空值 `-` 兜底"这一层散落在 6 处，阈值写法还不统一（`>1e12` vs `<1e12`，边界值语义相同但可读性差）。后端不同接口时间单位不统一（秒 / 毫秒）是客观事实，归一化本身必要，问题是重复实现。

**建议**：在 `utils/datetime.ts` 新增 `formatTimestamp(ts, { fallback, style })`，统一"归一化 + 兜底 + 委托本源"，6 处改为调用。**注意保留 3 处本页特化不动**：`DiskHealthChart.vue:157`（`MM-DD HH:mm` 紧凑轴标签）、`NotificationCenter.vue:164`（今天 / 昨天语义）、`realtimeFormat.ts` 的 `formatTime` 若被外部引用需保留导出名（可 re-export）。风险低—中，需逐处核对时间单位约定，建议配单测锁定归一化边界。

## 7. 修复落地记录（用户拍板后执行）

### 7.1 原生弹窗统一（对应 §2.1）

范围比初版多 1 处：读码时发现 `usePacketReplay.ts:143` `doDelete` 还用了原生 `confirm()`，同属"原生弹窗一致性"债，一并纳入。

| 文件 | 改动 |
|---|---|
| `composables/acquisition/usePacketReplay.ts` | `doDelete` 原生 `confirm` → `confirmDelete()`（复用项目全仓唯一确认封装，`src/utils/confirm.ts`）；`saveAsNew` 原生 `prompt` → `ElMessageBox.prompt`（`inputValue` 传默认值「XX（副本）」） |
| `views/acquisition/packet/PacketCapture.vue` | `saveAsSession` 原生 `prompt` → `ElMessageBox.prompt`（`inputValue` 传 `defaultSessionName()`） |

**关键契约**：用户取消不得触发写操作。原生 prompt 取消返回 `null`、confirm 返回 `false`；换成 Element Plus 后 prompt 取消走 `reject`（用 `try/catch` 吞掉并 `return`）、confirm 由 `confirmDelete` 封装转成 `false`。新建 `usePacketReplay.dialog.spec.ts`（4 例）与给 `PacketCapture.spec.ts` 追加 2 例，分别钉住"确认才保存/删除、取消不落库"。

### 7.2 formatTime 收敛（对应 §2.2）

在 `utils/datetime.ts` 新增单一本源 `formatTimestamp(input, opts)`：

- `unit: 'auto' | 'sec' | 'ms'` —— 显式声明输入单位，替代散落各处的 `t > 1e12 ? t : t*1000` 阈值写法；
- `style: 'datetime' | 'time'` —— 输出完整时间或仅时分秒；
- `fallback` —— 空值/无效值兜底文案（默认空串）；
- 边界口径统一：`1e12` 当毫秒、数值 `<= 0` / NaN / 非有限数一律返回 fallback（初版两处阈值写法 `>1e12` vs `<1e12` 在边界值上语义分歧，现已归一）。

6 处本地 `formatTime` 保留原导出名作为薄包装，内部委托本源（避免破坏模板/跨模块调用方）：

| 文件 | unit / style / fallback | 依据 |
|---|---|---|
| `composables/uplink/useUplinkTester.ts` | ms / time / '' | 历史时间戳已是毫秒（旧实现直接 `formatTimeOfDay(t)`） |
| `composables/config/useConfigVersions.ts` | sec / datetime / '-' | 配置版本时间戳约定为秒（旧实现无条件 ×1000） |
| `composables/data/useHistoryQuery.ts` | ms / datetime / '-' | 历史导出时间戳已是毫秒（f8 修复结论） |
| `views/uplink/UplinkPassthrough.vue` | auto / datetime / '-' | 接口单位由后端决定 |
| `views/system/maintenance/CellularStatus.vue` | auto / datetime / '-' | 接口单位由后端决定 |
| `utils/realtimeFormat.ts` | auto / time / '-' | 跨模块导出名，保留函数签名 |

**3 处本页特化按要求不动**：`DiskHealthChart.vue`（紧凑轴标签）、`NotificationCenter.vue`（今天/昨天语义）、以及 `datetime.ts` 自身的 `formatDateTime`/`formatTimeOfDay`（本源，被 formatTimestamp 委托）。

`utils/datetime.spec.ts` 新增 6 例 `formatTimestamp` 测试，锁定三种单位、style、1e12 边界与空值兜底。

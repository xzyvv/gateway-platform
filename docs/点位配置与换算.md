# 点位配置与工程量换算说明

**面向对象**：现场工程师 / 配置点位的人员。
**回答的问题**：点位上送的值是怎么算出来的？`scale` / `offset` / `formula` / CT / PT 各自什么时候生效、按什么顺序算？各协议的地址和数据类型怎么填？写下去的值为什么会和读回来的值对不上？

换算逻辑的代码单源：[`gateway-core/src/south/protocol/common/decode.rs`](../gateway-core/src/south/protocol/common/decode.rs)（`convert_value` / `reverse_convert`）与 [`gateway-core/src/config/point.rs`](../gateway-core/src/config/point.rs)（变比生效范围判定）。解码与 Web 配置体检共用同一套判定表，不存在两套口径。

---

## 1. 换算管线

### 1.1 读路径（采集上送）

```
设备原始值 raw
   │  ① 工程量换算（二选一）
   │     - 配了 formula：按公式计算（优先）；公式执行失败回退 scale×raw+offset，并记 warn
   │     - 未配 formula：raw × scale + offset
   ▼
二次侧工程量
   │  ② CT/PT 变比（按点位 unit 决定是否生效，见 §2）
   │     × ct_ratio（电流互感器变比，如 150/5 = 30）
   │     × pt_ratio（电压互感器变比，如 10000/100 = 100）
   ▼
一次侧真实值（上送 MQTT / Webhook / 前端展示 / 告警判定的就是这个值）
```

- `raw_value` 字段始终保留协议解析出的原始值，`value` 字段是换算后的值；排障时先对比这两个字段即可定位是「采集错」还是「换算错」。
- 换算结果为 NaN / ±Inf 时（公式错、变比放大溢出等）**fail-closed 回退到 raw** 并记 warn，不会把 NaN 上送（下游 SQLite / JSON 都会出问题）。

### 1.2 写路径（北向下发）

与读路径严格对偶，顺序相反：

```
下发的工程量（一次侧值）
   │  ① ÷ (CT × PT)（同样按 unit 门控；变比 ≤0 / 非有限值时跳过，不反算）
   ▼
二次侧工程量
   │  ② (工程量 − offset) ÷ scale   → 设备原始值
   ▼
写入设备
```

先除变比再反解 scale/offset 的顺序是有意的：否则 PT/CT 倍率会把 offset 一起放大，写下去的值和读回来的值对不上。formula 无法反推，写路径不反推公式（沿用既有行为）。

**例外：IEC104 写入不做反算。** IEC 104 的遥设/遥控命令（C_SE / C_SC）按标准语义携带的就是工程设定值，由从端自行标定，网关直接透传 `value`。这是协议语义差异，不是遗漏。

## 2. 换算字段参考

| 字段 | 默认 | 语义 | 注意 |
|---|---|---|---|
| `scale` | `1.0` | 倍率：`raw × scale + offset` | 配 0 会让读路径恒等于 offset、写路径除 0，**禁止**；配置校验会拦 |
| `offset` | `0.0` | 偏移：加在 scale 之后 | 注意变比在 offset 之后才乘（见 §1 顺序） |
| `formula` | 空 | 表达式，**优先于** scale/offset | 执行失败自动回退 `scale×raw+offset` 并记 warn，排障先搜 `formula` 关键字日志 |
| `ct_ratio` | 空 | 电流互感器变比（如 150/5 填 `30`） | 必须 > 0；是否生效由 `unit` 决定（§3） |
| `pt_ratio` | 空 | 电压互感器变比（如 10000/100 填 `100`） | 必须 > 0；是否生效由 `unit` 决定（§3） |
| `unit` | 空 | 单位，**决定变比生效范围** | 见 §3 单位门控表；留空按「都生效」处理 |
| `data_type` | 随协议 | 解码/编码的数据类型 | 各协议取值不同，见 §4 |
| `byte_order` | `ABCD` | 多字节字段字节序 | 仅 Modbus / FINS / MC / 电表二进制模式有意义，见 §5 |
| `interval` | 必填 | 采集周期（秒，≥1） | 影响磁盘占用，见 [`容量规划.md`](容量规划.md) |
| `writable` | `false` | 写白名单：`false` 时拒绝一切下发 | 工业现场默认拒绝写 |

**变比填错值的兜底**：配置校验要求变比 > 0；存量配置里出现 `0` / 非法值时，加载期自动降级为「不应用」并记 warn（网关不会因为一份旧配置拒绝启动）；Web 配置体检对「单位不在生效范围却配了变比」报 warning（如电压点位配了 CT）。

## 3. CT/PT 变比的单位门控

变比只对「二次侧 → 一次侧」有物理意义的量生效，**按 `unit` 判定**（判定表在 [`config/point.rs`](../gateway-core/src/config/point.rs) 的 `ratio_scope`，前后端共用同一套）：

| 单位 | CT | PT | 举例 |
|---|---|---|---|
| 电压（`V` `kV` `mV`，大小写不敏感） | ✗ | ✓ | 母线电压只乘 PT，误配 CT 会被放大 30 倍 |
| 电流（`A` `kA` `mA`） | ✓ | ✗ | 电流只乘 CT |
| 功率 / 电量（`W` `kW` `var` `kWh` `kVarh` …） | ✓ | ✓ | P = U × I，两者都乘 |
| 功率因数（`PF` `cosφ` `cos` `功率因数`） | ✗ | ✗ | 无量纲，都不乘 |
| **单位留空 / 不在清单内** | ✓ | ✓ | 兼容旧行为（无条件连乘）；**建议填准单位**，既解锁门控也解锁体检 |

> 单位匹配不区分大小写。要新增受控单位，改 `ratio_scope` 的单位表并同步前端 `useRatio.ts::ratioScopeOf`。

## 4. 各协议地址与数据类型语义

`data_type` / `address` 的语义**随协议变化**，不能跨协议照抄：

| 协议 | `point.address` | `data_type` 取值 |
|---|---|---|
| Modbus | `address` = 从站号串；`address_num` = 寄存器偏移（0 基，实际寻址用这个）；前端展示的 5 位地址 = 功能码头 + 1 基偏移（如功能码 4、偏移 9 → `40010`） | `u16` `i16` `u32` `i32` `u64` `i64` `f32` `f64`（历史别名 `uint16` `int16` `float` `double` 等仍可解析，加载/保存模板时会自动归一为规范名） |
| DLT645 | `address` = BCD 表地址；`data_id` = 数据标识 | 默认 BCD 解码；配成二进制类型后按类型 + 字节序解码 |
| CJT188 | `address` = 表号；`data_id` = 数据标识 | 同 DLT645 |
| IEC 104 | `address` = IOA（十进制串） | **自有语义**：`float`（默认）`normalized` `scaled` `single`。**不是** Modbus 类型别名，不要填 `u16` 之类 |
| S7Comm | `address` = PLC 存储区编址：DB 区 `DB1.DBD0`（DWord/REAL）`DB1.DBW0`（Word/INT）`DB1.DBB0`（Byte）`DB1.DBX0.0`（Bit）；也可用 M/I/Q 区（如 `MD100`、`IW0`、`Q0.0`）；设备侧连接地址格式 `host:102?rack=0&slot=2` | 地址后缀自带宽度语义；`data_type` 可作解析提示（如 `real`） |
| BACnet | `address` = `对象类型:实例号`，如 `analog-input:1` 或 `0:1`（0=AI 1=AO 2=AV 3=BI 4=BO 5=BV） | 无 |
| FINS（欧姆龙） | `address` = 存储区地址：`D100` `CIO0` `W200` `EM10`；写也可指 `CPU:RUN` / `CPU:STOP` | `u16`（默认）`i16` `u32` `i32` `u64` `i64` `f32` `f64` `bit` |
| MC（三菱） | `address` = 软元件地址：`D100`（字）`M10`（位）`ZR1000` | `u16`（默认字元件）`i16` `u32` `i32` `u64` `i64` `f32` `f64` |

IEC 104 读值只有总召唤快照一条路（104 没有「读单个 IOA」的请求帧），IOA 不在快照里时该点无值而非报错。

## 5. 字节序（`byte_order`）

仅对多字节二进制字段有意义（Modbus / FINS / MC / 电表二进制模式）；BCD 与 IEC 104 / S7 / BACnet 不使用。

| 值 | 含义（4 字节示例 `0x12345678`） |
|---|---|
| `ABCD`（默认） | 大端原序：12 34 56 78 |
| `DCBA` | 完全反序：78 56 34 12 |
| `CDAB` | 字交换：56 78 12 34（常见于部分 Modbus 设备的 f32） |
| `BADC` | 半字交换：34 12 78 56 |

读写走同一份 `byte_order` 配置且重排互为对合，写→读往返不会串序。

## 6. 读写对称性支持矩阵

| 协议 | 读路径换算（scale/offset/formula + CT/PT） | 写路径反算 |
|---|---|---|
| Modbus | ✓ | ✓（线圈/位写除外——布尔量无换算） |
| DLT645 / CJT188 | ✓ | ✓ |
| FINS / MC | ✓ | ✓（字写；位元件布尔写除外） |
| S7Comm | ✓ | ✓ |
| BACnet | ✓ | ✓ |
| IEC 104 | ✓ | 不反算（遥设按工程值透传，见 §1.2 例外说明） |

未配置任何换算字段时（scale=1.0、offset=0.0、无变比、无公式），换算是恒等映射——**存量点位不需要为升级做任何改动**。

## 7. 设备模板里的换算字段

设备模板（`gateway-core/src/config/template.rs`）的点位支持携带：`function_code` / `data_type` / `unit` / `scale` / `offset` / `formula` / `ct_ratio` / `pt_ratio`，展开成实际点位时原样透传。

- 模板 `description`：随模板 JSON 分发的自解释备注，无运行时作用。
- 模板点位的 Modbus「地址」填 **0 基寄存器偏移**，展开后前端按功能码渲染成 5 位展示地址。
- 模板数据类型别名（`float` / `int16` 等）：加载和保存模板时自动归一为规范名，**仅对 Modbus 协议生效**（IEC 104 的 `single` / `normalized` 是自有语义，不受影响）。
- 变比同样要求 > 0，模板校验会拦。

## 8. 常见误配速查

| 现象 | 先查 | 依据 |
|---|---|---|
| 上送值比现场表计大 30 倍 | 电压点位是否误配了 `ct_ratio`；或 `unit` 留空导致 CT/PT 都生效 | §3 门控表 |
| 配了 scale 但实时值没变化 | 看实时数据的 `raw_value` 是否在变：不变是采集问题，变而 `value` 不换算是点位没保存成功 | §1.1 |
| 实时值是 NaN 或 null | 公式语法错误（日志搜 `formula ... failed`）或变比放大溢出；网关已回退 raw 并记 warn | §1.1 兜底 |
| 写下去的值读回来不对 | `unit` 是否两侧一致（写反算按 unit 门控）；scale 是否为 0；确认不是 IEC 104（透传语义见 §1.2） | §1.2、§6 |
| 实时数据里类型显示裸字符串 `f32` | 前端类型标签映射缺项（已在 `realtimeFormat.ts` 兼容规范名与历史别名） | §4 |
| 改了点位配置不生效 | 保存后生效方式见 [`config-reload-matrix.md`](config-reload-matrix.md) 的配置生效矩阵 | — |

现场故障排查入口另见 [`故障处置卡.md`](故障处置卡.md)；装机前整体检查见 [`装机前准备清单.md`](装机前准备清单.md)。
